---
title: Run and test code
summary: Run a program, test it, and know what to do when a computer cannot run a language.
---

Use this guide when you want to try a program yourself, or when you show students how to check their work before they submit.

## Run a program

1. Open the file you want to run.
2. Choose **Run** in the status bar, the strip at the bottom of the window. You can also press F5.
3. Read the output in the Run panel. If the program asks for input, type it in the line under the panel and press Enter.
4. To stop the program, choose **Stop** or press Shift+F5.

**Run** runs what you are working on. Point at it to see what it will run and why. To run something else, use **Change Run Target…**.

## Test a program

1. Choose **Test**, beside **Run**. It shows how many tests passed out of the total.
2. To write a simple test, choose **Add a Test**. Give an example input and the output you expect. TMCode writes the test for you.
3. Read the results in the Testing view. Failures come first, each with its message.

The colours mean: green passed; red wrong answer, crash or did not compile; orange a limit, such as too slow.

> **Note:** When you check a coding question with your own unit tests, students cannot run your tests. They run only their own. Your tests check the work when they submit.

## When the computer cannot run the language

Before a run, TMCode checks that the language is installed. If it is not, a card says so and offers these choices:

- **How to Install** shows how to add the language to the computer.
- **Check Again** tries once more after you install it.
- **Run on Task Mentor** runs the program on Task Mentor and shows the output in the Run panel. This works in exams too.

## Check a computer before a lesson

1. Open the Help menu.
2. Choose **Check My Computer**.
3. Read the result. It lists the languages TMCode found on the computer.

## If something goes wrong

- **Run on Task Mentor does not appear.** It shows only when your school's Task Mentor offers it.
- **A program waits and nothing happens.** It is probably waiting for input. Type in the line under the Run panel, or choose **End of Input** to tell the program there is nothing more to read.
